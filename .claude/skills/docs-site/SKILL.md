# Documentation site

One source of truth: Markdown files inside the UPM package. The same file is read by
GitHub, by Unity (as a `TextAsset` in the Inspector) and by the Docusaurus site in `Docs/`.
Nothing is copied. Write GitHub Flavored Markdown; the site adapts to it, never the other way round.

## Layout

| What | Where | Site route |
|---|---|---|
| Main docs (guide, StarterKit reference) | `Aspid.MVVM/Packages/tech.aspid.mvvm/Documentation/**/*.md` | `/docs/...` |
| Tutorials | `Aspid.MVVM/Packages/tech.aspid.mvvm/Samples~/<Sample>/README.md` | `/tutorials/<slug>` |
| Translations | `Documentation/<locale>/**` (same tree) and `Samples~/<Sample>/README.<locale>.md` | `/<locale>/...` |
| Site config | `Docs/docusaurus.config.js`, `Docs/sidebars.js`, `Docs/sidebarsTutorials.js` | |
| CI | `.github/workflows/docs.yml` → GitHub Pages `https://vpdpersonal.github.io/Aspid.MVVM/` | |

Two docs plugin instances: the default one (`docs`) points at `Documentation/` (translation folders
excluded), the second (`id: 'tutorials'`) points at `Samples~/` with `include: ['*/README.md']`. Only
Markdown matching `include` is read; scripts, scenes and `.meta` files are never touched.

Translations live in the package too. `Docs/scripts/sync-i18n.mjs` (run by `prestart`/`prebuild`) copies
`Documentation/<locale>/` and every `README.<locale>.md` into the `Docs/i18n/` layout Docusaurus expects.
`Docs/i18n/` is a build artifact and is gitignored; never edit it by hand. Copies, not symlinks: webpack
resolves symlinks to the real path and the relative links inside a translation stop resolving.

`SUMMARY.md` is a GitBook leftover kept as the GitHub table of contents. It is excluded from
the site; the site sidebar is autogenerated from the folder.

## Writing rules (so all three renderers agree)

- **No front matter.** Unity and GitHub would show it as text. Title comes from the first `# H1`,
  slug and order come from the file/folder name.
- **Admonitions**: GitHub style only.
  ```md
  > [!NOTE]
  > Text.
  ```
  Allowed: `NOTE`, `TIP`, `IMPORTANT`, `WARNING`, `CAUTION`. Never `:::note`.
- **Links** are relative paths to the `.md` file, spaces as `%20`:
  `[Greeter](../02.%20Greeter/README.md)`, `[Binders](../../Documentation/06-binders.md)`.
  GitHub follows them as files. Docusaurus resolves links inside one plugin instance itself; links
  that cross from a sample README into `Documentation/` (or back, `../Samples~/<Folder>/README.md`)
  are rewritten to site routes by `Docs/src/remark/crossInstanceLinks.js`. Never link by site URL.
- **One `# H1` per file.** Extra H1s in the body get no anchor id on the site; use `##`.
- **Anchors** to headings must match a heading that exists; the build warns on stale ones.
- **Images** live next to the file (`Documentation/Images/`), referenced relatively.
- **Sample `README.md`** doubles as the tutorial. Keep the sample facts at the top (scene table,
  files) and the fonts note at the bottom; the tutorial body goes between.
- The package is English. A translation is a sibling file: `Documentation/ru/06-binders.md` next to
  `Documentation/06-binders.md`, `README.ru.md` next to `README.md`. Missing pages fall back to English.
- A translated file links translated targets (`../../Documentation/ru/06-binders.md`,
  `../02.%20Greeter/README.ru.md`) so GitHub stays in the same language; the site drops the locale segment
  and prefixes the route with the current locale itself.
- Adding a language: create `Documentation/<locale>/` and/or `README.<locale>.md` files and add the locale
  to `LOCALES` in `docusaurus.config.js`. Nothing else.

## Slugs and ids (tutorials)

`samplePrefixParser` in `docusaurus.config.js` turns the folder name into a slug:
`01. Counter` → `counter` (position 1), `VirtualizedList` → `virtualized-list`, `DynamicViewModel` →
`dynamic-view-model`. `README.md` is the folder's index document, so the route is `/tutorials/counter`
and the doc id used in `sidebarsTutorials.js` is `counter/readme`. `crossInstanceLinks.js` has a copy
of the same slug rules; change both together.

Main docs use the default parser: `03-binding-modes.md` → `/docs/binding-modes`,
`StarterKit/README.md` → `/docs/StarterKit`, `Documentation/README.md` → `/docs`. The site root `/`
redirects to `/docs` (`Docs/src/pages/index.js`).

## Adding a tutorial / sample

1. Create `Samples~/<NN. Name>/README.md` (plus its `.meta`, but not the folder in git index — leave new files untracked for review).
2. Add `<slug>/readme` to `Docs/sidebarsTutorials.js` under `Path` or `Features`.
3. Register the sample in `package.json` → `samples` as usual.
4. Optionally add `README.ru.md` next to it.

Missing translations fall back to English automatically.

## Adding a main doc page

Drop the file into `Documentation/` (numbered prefix `NN-` orders it) and add its entry to `SUMMARY.md`.
Optionally add the translation at `Documentation/ru/<same name>`. Nothing to change in `Docs/`.

## Versioning

Cut a version when the package version is released:

```bash
cd Docs
npm run version 1.1.0          # main docs → Docs/versioned_docs/version-1.1.0
```

Tutorials are not versioned: a tutorial always describes the sample shipped with the same package version.
The version dropdown in the navbar reads `Docs/versions.json`.

## Local run / check

```bash
cd Docs
npm ci
npm start                # http://localhost:3000/Aspid.MVVM/ (prestart syncs translations)
npm run start:ru         # Russian locale (dev server serves one locale at a time)
npm run build            # what CI runs; fails on broken links
```

`onBrokenLinks` and `onBrokenMarkdownLinks` are set to `throw`: a bad relative link breaks the build on purpose.

## API reference (`/api`)

The **API** tab is generated from the XML doc comments by DocFX, not written by hand. `Docs/api/` holds the
generated Markdown plus `sidebar.js` and **is committed**: DocFX has to compile the assemblies against the
local Unity installation, which CI does not have.

```bash
dotnet tool install -g docfx        # once
cd Docs && npm run api              # regenerate after public API or XML doc changes
```

`npm run api` runs three steps (`Docs/scripts/docfx-*.mjs`, `Docs/docfx/docfx.json`):

1. `docfx-projects.mjs` rewrites the legacy `.csproj` files Unity generates (`Aspid.MVVM`, `Aspid.MVVM.Unity`,
   `Aspid.MVVM.StarterKit`) into SDK-style projects under `Docs/docfx/projects/` (gitignored, absolute paths)
   with the same files, references, defines and the source generators as analyzers. Unity must have regenerated
   the `.csproj` files and `Library/ScriptAssemblies` first (open the project once).
2. `docfx metadata` writes one Markdown page per type into `Docs/api/`.
3. `docfx-postprocess.mjs` makes it MDX-safe: `<xref>` → links (own pages, learn.microsoft.com, Unity Scripting
   Reference), `<pre><code>` → fenced code, heading anchors as `{#id}`, escaped `<T`/`{}`, no "Inherited Members",
   front matter with a short `sidebar_label`, and `toc.yml` → `sidebar.js` (namespace → Classes/Interfaces/… groups).

The pages are served by a third docs plugin instance (`id: 'api'`) in `docusaurus.config.js`. Never edit files in
`Docs/api/` by hand; fix the XML comment or the postprocess script and regenerate. Translations are not
generated; the `ru` locale falls back to the English pages.

## Design

The theme is a dark graphite with the Unity badge green as accent (see the `--venom-*` tokens); light mode is
pastel beige. Fonts: IBM Plex Serif (headings), iA Writer Quattro (body, self-hosted in `Docs/src/fonts/`),
IBM Plex Mono (code and UI labels).

- `Docs/src/css/custom.css`: tokens at the top (`:root` light, `html[data-theme='dark']` dark), Infima
  overrides, the Delta-style three-panel docs layout (`html.docs-doc-page`), gemstone colours for admonitions.
  Panels are square, the article scrolls inside its own panel; `Docs/src/clientModules/panelScroll.js` forwards
  that scroll to `document` so the TOC highlight keeps working.
- `Docs/src/prism/venom.js`: Prism themes for code blocks. Dark is Ayu Dark as rendered by Rider
  (background `#0e1015`); light is Ayu Light on cream.
- `Docs/src/pages/index.js` + `index.module.css`: the landing page (hero, stats, before/after, data-flow diagram,
  Inspector mock, features, sample path, CTA). All strings go through `<Translate>` so `npm run write-translations`
  picks them up. The Inspector block is a CSS mock until a real screenshot replaces it.
- `Docs/static/img/logo.svg` (light) and `logo-dark.svg` (dark): navbar logo; `favicon.svg`.
- The version dropdown shows the package version read from `package.json`; `sidebars.js` pins `README.md` as
  "Introduction" at the top and relabels the StarterKit category.

Check both themes after a change: build, `npx docusaurus serve`, and screenshot with headless Chrome (set
`localStorage.theme = 'light'` through the DevTools protocol; `defaultMode` is dark). Do not run `npm run build`
while a dev server is running from the same folder: they share `.docusaurus/`, `i18n/` and
`node_modules/.cache`, and the dev server starts crashing with `Cannot read properties of undefined (reading 'id')`.
Build a copy of `Docs/` (with a real copy of `node_modules`, not a symlink) instead, or stop the dev server.

## Deploy

`.github/workflows/docs.yml` builds on every push to `main` touching `Docs/`, `Documentation/` or a
sample `README.md`, and on PRs (build only). Pages source must be set to "GitHub Actions" once in the
repository settings.
