# Aspid.MVVM

A high-performance Source Generator-based MVVM framework for Unity. Enables clean separation between View, ViewModel, and business logic with zero reflection in bindings and minimal memory allocations.

## Key Technologies

- **C# / .NET Standard 2.0** — core framework
- **Roslyn Incremental Source Generators** — code generation at build time
- **Unity 2022.3+** — target runtime
- **Zenject / VContainer** — DI framework integrations
- **UniTask** — async utilities
- **.NET SDK 10.0.300** — for generator/analyzer projects (root `global.json`); test projects target `net9.0`

## Architecture

The framework uses Source Generators to eliminate boilerplate and reflection:

1. **`[ViewModel]`** — marks a `partial` class for source generation; generates `IViewModel` implementation
2. **`[Bind]`** — marks fields for binding generation; supports `BindMode` argument
3. **`[RelayCommand]`** — transforms a method into an `IRelayCommand` property
4. **Binders** — MonoBehaviour components that connect View UI elements to ViewModel bindable members
5. **Observable Collections** — thread-safe, change-notifying collections with filtering/sorting

## Code Conventions

**Naming:**
- `PascalCase` for classes, interfaces, methods, properties
- `camelCase` for local variables and parameters
- `_camelCase` prefix for private fields
- `I` prefix for interfaces (`IViewModel`, `IRelayCommand`)
- `Binder` suffix for binding components, `Attribute` suffix for attributes

**Namespaces:**
- Root: `Aspid.MVVM`
- Sub-namespaces: `Aspid.MVVM.StarterKit`, `Aspid.Collections.Observable`
- Editor code lives in `.Editor` sub-namespaces

**Code Style:**
- All classes requiring source generation must be `partial`
- Explicit access modifiers on all members
- Nullable reference types (`T?` for optional values)
- XML documentation comments on all public APIs; conventions in global skill `asp-xmldoc`. Aspid-specific `<param>` phrasing: binding mode `The binding mode. [constraints]`, converter `The converter used to transform X to Y.`, bound enum value `The bound enum value received from the ViewModel.`, target object `The X to bind.`
- ReSharper suppression comments on generated/special code

## Commands

Generator/analyzer solutions build independently of Unity:

```bash
# Rebuild the three Roslyn DLLs in Release and copy them into the package (commit the result)
scripts/build-roslyn-dlls.sh

# Run generator tests
dotnet test Aspid.MVVM.Generators/Aspid.MVVM.Generators/Aspid.MVVM.Generators.Tests/

# Run analyzer tests
dotnet test Aspid.MVVM.Analyzers/Aspid.MVVM.Analyzers/Aspid.MVVM.Analyzers.Tests/

# Run the tests of the CI scripts
node --test scripts/*.test.mjs

# Set the release version: package.json, README install URLs, the dated CHANGELOG sections and links
scripts/set-version.sh 1.1.0-rc.1
```

### Releases

Only a pushed `v<version>` tag on a commit of `main` starts `.github/workflows/release.yml`: preflight (SemVer, the commit is in `main`, `upm/<version>` is new, package.json, the CHANGELOG section) → the whole `ci.yml` with Unity required → one atomic push of the `upm` (stable) or `upm-preview` (prerelease) subtree branch and its `upm/<version>` tag, with CHANGELOG/MIGRATION (+ `.ru`) bundled into the package → the GitHub release (`gh`). There is no manual run: the `Release tags` ruleset lets only admins push `v*` tags. Skill [asp-mvvm-release](.claude/skills/asp-mvvm-release/SKILL.md) walks the release (bump PR, merge, tag, watching the run).

### Unity Editor automation (Unity CLI)

Editor automation goes through the official **Unity CLI** (`unity`) and the `com.unity.pipeline`
package, which is declared in `Aspid.MVVM/Packages/manifest.json`. A running Editor exposes ~140
commands over its Pipeline server, called as `unity command <group> <name>` (Pipeline 0.9+):

```bash
# Open the project and check that the Pipeline server is up
unity open Aspid.MVVM
unity status --json

# Discover / run Editor commands
unity command                                  # list every command the Editor exposes
unity command <group>                          # list the commands of one group
unity command script recompile --json          # compile check after C# edits
unity command package resolve --json           # re-resolve packages after a manifest change
unity command console get --json               # read the Editor console
unity command test run --mode editor --json    # Unity Test Framework run (EditMode)
unity command script eval --code 'return Application.unityVersion;'
```

When several Unity Editors are open, add `--project-path ./Aspid.MVVM` — otherwise the CLI can't
pick an instance and errors out.

AI agents can consume the same command surface as MCP tools: the repo ships `.mcp.json` with a
`unity-editor` stdio server (`unity mcp --project-path ./Aspid.MVVM`).

## Gotchas

- **Generator artifacts are committed.** Built DLLs (`Aspid.MVVM.Generators.dll`, `Aspid.MVVM.Analyzers.dll`, `Unity/Aspid.MVVM.Unity.Generators.dll`) live under `Aspid.MVVM/Packages/tech.aspid.mvvm/` and are checked into the repo. After changing a generator or an analyzer, run `scripts/build-roslyn-dlls.sh` and commit the refreshed DLLs — Unity consumes the DLL, not source. The Roslyn DLLs job of CI rebuilds them and fails on any byte of difference; the root `Directory.Build.props` makes the Release build reproducible.
- **The .NET SDK is pinned** to `10.0.300` by the root `global.json` (`rollForward: disable`): another compiler gives other DLL bytes. The test projects target `net9.0`, so `dotnet test` also needs the .NET 9 runtime.
- **Classes using `[ViewModel]`, `[Bind]`, `[RelayCommand]` must be `partial`** — the generator emits a second partial; without the modifier you get compile errors instead of generated members.

## Roslyn sources

`Aspid.MVVM.Generators/`, `Aspid.MVVM.Analyzers/` and `Aspid.MVVM.Unity.Generators/` were separate repositories
consumed as git submodules; their full history is merged here, and their old tags carry the `generators/`,
`analyzers/` and `unity-generators/` prefixes. A change to one of them goes in the same PR as the DLL it rebuilds.
A clone made before the merge runs `git submodule deinit -f --all` once before it checks out a commit without the
submodules; otherwise git cannot replace the old submodule folders with tracked ones.

`Aspid.Collections` is consumed as a UPM git package (`tech.aspid.collections`).
