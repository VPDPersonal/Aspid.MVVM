## [Unreleased]

### Added

- **Resetting an animator trigger.** A trigger that was set and never consumed stays armed, and the animation fires the moment its state becomes reachable — often seconds later, in a state nobody connected to it. Nothing in the package could undo that. `AnimatorResetTriggerMonoBinder` and `AnimatorResetTriggerBinder` do, and they cost almost nothing to add because the command plumbing they need was extracted from the Set binders into a shared base rather than copied: `AnimatorTriggerMonoBinder` and `AnimatorTriggerBinder` own the `IRelayCommand`/`Action` handover, the parameter check and the enabled-state notification, and each leaf supplies one line.
- **`ListView.itemsSource`, the last UI Toolkit family.** A `ListView` owns its recycling, so this binder creates and releases nothing: it hands the list a source and tells it what changed, leaving `makeItem` and `bindItem` where they belong. An observable collection is followed and the list refreshed on every change — the granular calls need an index, and a filtered list reports none. The ViewModel's collection is wrapped rather than handed over, even when it already implements `IList`, because the list view would otherwise be able to write into it; the wrapper does not copy, so the cost is one object per binding and every mutating member throws. The source is cleared when the binding is released, so a recycled panel does not show the previous ViewModel's items for a frame.
- **Binders for the set, the queue and the stack.** Lists and dictionaries were bound and the other three types of the collections library were not, though a set of owned ids, a queue of pending requests and a stack of open screens are all things a View shows. `ObservableCollectionMonoBinder<T>` covers all three, because that is exactly what they have in common: membership that changes, and no index worth binding to. It is deliberately not built on the list binder — a list binder's hooks carry an index, and none of these three has one that survives a change, since a queue renumbers on every dequeue. `ObservableCollectionViewModelMonoBinder` creates a view per member and releases it when the member leaves, holding views by the ViewModel they show rather than by position. What the collection already holds is replayed when it arrives, and a change reported without detail rebuilds rather than guessing at what moved.
- **The MonoBehaviour half of the dictionary domain.** The list domain had both a serializable binder and a component one; the dictionary domain had only the serializable one, so a dictionary could be shown from a View's own field and not from a component dropped next to the objects it drives. `ObservableDictionaryMonoBinder<TKey, TValue>` dispatches exactly what its serializable twin dispatches, and `ObservableDictionaryViewModelMonoBinder` creates a view per entry through a keyed factory and releases it when the entry goes away. What the dictionary already holds is replayed when it arrives, so a View built after the data still shows it. A replacement under an existing key releases the old view and creates a new one rather than re-initialising the old: a factory may hand out a different prefab for a different ViewModel.
- **`VideoPlayer` and `NavMeshAgent` binders.** The two external systems the audit listed as reasonable once the rest was covered. Five families: which video plays (`clip`, on the object base, so a destroyed clip arrives as `null`), how fast it plays, whether it loops, how fast an agent moves, and whether it moves at all. `playbackSpeed` is clamped to the 0..10 Unity documents — it accepts anything and then decodes at a rate the platform cannot sustain, which shows up as stuttering rather than as an error. `isStopped` is skipped while the agent is not on a navmesh: Unity throws for that case, and an exception inside a binding loop takes the rest of the View's bindings with it.
- **UI Toolkit binders — the runtime layer was uGUI and TextMeshPro from end to end.** A project on the stack Unity itself recommends could not use the framework at all. `VisualElementMonoBinder<TElement>` resolves one element inside a `UIDocument` by name or by USS class, and seven binders stand on it: `Label Text` (which accepts any bound value, not only a string), `Display` (through `style.display`, so a hidden element takes no space — which `visible` does not do), `Enabled`, `Class` (the idiomatic UI Toolkit way to express state: the look lives in the stylesheet and the ViewModel says only whether the state holds), `Button Command` (the button's enabled state follows `CanExecute`, the same way the uGUI binder drives `interactable`), and two-way `Slider Value` and `TextField Value`. The element is looked up lazily rather than at binding time, because a document builds its tree in `OnEnable` and a View that binds from `Awake` would otherwise search an empty root — the failure would look like a wrong name. A missing document, a blank name and a name that matches nothing are each reported once and not retried per value, since a UI Toolkit query walks the tree. The two-way binders guard against reading their own write back as user input, and release the guard in a `finally` — UI Toolkit raises the same change event for both directions.
- **A collection's size and emptiness as bindable values.** "Items: 12" and an empty-state panel are both derived from a collection the View already has, and neither could be bound: the ViewModel carried a count field and an emptiness flag next to the collection and kept all three in step by hand. `CollectionCountMonoBinder<T>` reports both, following an observable collection through every insert and removal; a plain `IReadOnlyList<T>` is read once, since there is nothing to listen to. A `null` collection reports zero and empty rather than nothing at all — a panel that says "nothing here" is the right answer to a list that has not arrived. `ObjectCollectionCountMonoBinder` is the ready closure: the collection interfaces are covariant, so a list of any class is accepted without a subclass per element type, and a project binding a collection of a value type writes the one-line subclass.
- **Aggregators — an answer that depends on several members at once.** A binder binds one member, which is the right shape for a value and the wrong one for "is the button available", whose answer depends on three of them; composition existed only for collection filters, so the workaround adds a fourth field to the ViewModel that exists to hold the answer. The shape here keeps the framework's rule intact: each input is an ordinary binder bound to its own member (`BoolAggregatorInputMonoBinder`, `StringAggregatorInputMonoBinder`) writing into a shared aggregator under its own index, and the aggregator forwards the combined value — `AndBoolMonoBinder`, `OrBoolMonoBinder`, `FormatStringMonoBinder`. Nothing is forwarded until every input has reported once: with an `And` over three conditions, two arriving first would enable a button the third immediately disables. A format string that does not match its inputs is reported rather than thrown, because an exception inside a binding loop takes the rest of the View's bindings with it, and a `null` part composes as an empty string rather than the word `null`. Alongside them, `ConditionalFloat`, `ConditionalString` and `ConditionalColorMonoBinder` turn a bound boolean into one of two values configured in the Inspector — the two-state case that is neither a colour block nor a sprite swap, and that otherwise puts the view's wording into the ViewModel.
- **`RectMask2D.padding`.** How far the mask is inset on each side — what a safe area, a notch or a sidebar that slides in changes at runtime. The component had no binder at all. The property is a `Vector4` and the bound value is a `Vector3`, so the fourth side keeps whatever it had: binding three sides does not silently zero the fourth.
- **Rate limiting: debounce, throttle and delay.** A search field publishes a value per keystroke and a high-frequency source publishes one per frame. Nothing in the package could space those out, so a ViewModel either sent every one — a request per character — or grew a timer of its own, which is the frame-rate concern the framework exists to keep out of it. Three policies over one base, each with a `Float` and a `String` closure: a **debounce** holds a value until the values stop, so a fast typist produces exactly one; a **throttle** lets the first value through at once and then at most one per interval, holding the newest in between, because waiting out the interval before showing anything makes a view look broken; a **delay** drops nothing and forwards every value late and in order, which is what a staggered reveal needs. All three are casters, so the spaced-out values drive whatever binder listens. Releasing the binding drops whatever was waiting — a value that belonged to the previous binding must not arrive after it, which is exactly what a pooled list row would do. The clock is unscaled by default, so a menu keeps working while the game is paused.
- **Tween binders — the first interpolation in the package.** There was no `Lerp` anywhere in the binder set, so a health bar bound to a health value jumped, and the usual workaround holds a second animated value in the ViewModel and drives it from an update loop — which puts frame-rate concerns into the layer that is supposed to be free of them. `TweenFloatMonoBinder`, `TweenColorMonoBinder` and `TweenVector3MonoBinder` ease each value they receive and forward every intermediate one to a `UnityEvent`, so the same tween drives an image fill, a text number or a position through whatever binder is listening. A new value while a tween is running retargets it from where it currently is, which is what makes a bar chase a moving number instead of restarting. The first value after binding passes through instantly — easing from a type's default would flash a bar from empty — and unbinding forgets the state, so a pooled list item does not ease out of the previous row's value. The clock is unscaled by default, so a pause menu still animates.
- **`MaterialPropertyBlock` binders — a shader value per object without a material per object.** The only path the package offered to a shader property was `Renderer.material`, which instantiates a copy on first touch: every bound object gets its own material, batching stops, and the copies leak into the scene — Unity says so in the console itself. Four binders write through a property block instead, leaving the material shared: `Float`, `Color`, `Vector` (which also takes a `Vector2` or `Vector3`, since shader vectors are always four components) and `Texture`. The block is created once and reused, and the property name is resolved to an id when binding is established rather than hashed on every value. A blank property name is reported once at binding time and nothing is written until it is filled in. The texture binder does not write a `null`: a property block cannot clear an override, so the previous texture would stay rather than the shader falling back to the material's own — which is the behaviour to design around, and it is documented rather than hidden.
- **The two ToSource binders that were missing, and `ToggleGroup`.** Eight domains handed the ViewModel their component reference and two did not: `SelectableToSourceMonoBinder` and `GameObjectToSourceMonoBinder` close that. The GameObject one exists as its own binder rather than as a component one, because a ViewModel that spawns a view and then has to move, parent or destroy it needs the object — walking from a component to `gameObject` inside the ViewModel means the ViewModel knows about Unity types it otherwise would not. `ToggleGroupAllowSwitchOffMonoBinder` binds the one property a `ToggleGroup` has, which had no binder at all: whether the group may end up with nothing selected — the difference between a filter the player can clear and a set of tabs that must always have one open.
- **The last two gaps in the AudioSource domain: a clip per event, and knowing when a sound ends.** `AudioSourcePlayOneShotMonoBinder` plays each clip the ViewModel publishes, mixed over whatever the source is already playing rather than replacing it — which is what a hit, a purchase or a level-up needs, and the reason it takes the clip from the ViewModel instead of from the component. A `null` or destroyed clip does nothing, so a field that starts empty is silent rather than an error. `AudioSourceIsPlayingToSourceMonoBinder` reports whether the source is playing, so a button that should re-enable itself when a voice line ends has something to listen to. `AudioSource` raises no event for this, so the state is polled in `Update` and the ViewModel is told only when it changes — one boolean comparison per frame per binder, which is why this is a binder a project adds where it needs it rather than something the playback binders do on their own. Nothing is polled while the component is disabled: a paused game does not report a sound as finished.
- **Binders for state that belongs to no component.** Pause, slow motion and a settings screen's graphics options each needed a MonoBehaviour written for the purpose, because the framework only bound components. Four global families — `Time.timeScale`, the active `QualitySettings` level, `Application.targetFrameRate` and `Screen.fullScreen` — plus three small UI ones that had no binder either: `Object.name`, `Shadow` `effectColor` and `effectDistance` (which `Outline` inherits, so one binder covers both effects) and `Mask.showMaskGraphic`. The time scale is clamped non-negative, because Unity refuses a negative one and logs an error; a non-finite value lands on zero, which pauses rather than leaving physics with a delta time it cannot use, and the binder points at the audio pause binder for the part the time scale does not do. The quality level is clamped to the levels the project defines — Unity throws on an index it does not have. The frame cap treats every negative value as `-1`, the only one that means anything: hand the decision back to the platform.
- **Animator control: speed, layer weight, controller and playing a named state.** The domain bound the parameters a controller reads and neither the clock it reads them on nor the controller itself, so slow motion, an additive layer fade and a rig that changes its whole animation set all lived outside the framework. `AnimatorSpeed` keeps negative values — playing backwards is legal — and refuses a non-finite one, which the animator accepts and then stops dead on. `AnimatorLayerWeight` takes the layer in the Inspector and the weight from the ViewModel, clamps it to 0..1, and reports a layer index the controller does not have instead of writing into nothing. `AnimatorController` is on the object base, so a destroyed controller arrives as `null`; its documentation says the thing that costs an afternoon otherwise — assigning a controller resets the state machine, though parameters keep their values. `AnimatorPlayState` plays the state the ViewModel names, which is how a cutscene or a one-off reaction is triggered without inventing a parameter and a transition for it; a blank name does nothing, so a field that starts empty does not make the animator jump.
- **The visual properties of components the package bound only in part.** Twelve families: `Image` `type`, `preserveAspect`, `fillOrigin` and `fillClockwise`; `RawImage.uvRect`; `LineRenderer` `widthMultiplier` and `loop`; `Renderer` `sortingOrder`, `sortingLayerName` and `shadowCastingMode`; `Selectable` `transition` and `targetGraphic`. `Image.fillAmount` was bound and the four options that decide what a fill looks like were not; `SpriteRenderer.sortingOrder` was bound and the same property inherited from `Renderer` was not, so a line, a mesh or a trail could not be brought to the front. `sortingLayerName` refuses a name no layer has with an error — Unity ignores it silently and leaves the object where it was, which looks exactly like a depth bug. `uvRect` refuses a non-finite component, which would make the image vanish, and `widthMultiplier` is clamped non-negative. `targetGraphic` is on the object base, so a destroyed graphic leaves the control untinted rather than pointing at something that no longer exists.
- **Scene-level properties: layer, parent, sibling order and the rect's anchors.** The package could bind a tag and not a layer, a position and not a parent, an anchored position and not the anchors — so the parts of a layout a responsive UI actually changes were the parts it could not reach. Eight families: `GameObject.layer`, `Transform.parent`, the transform's sibling index, and `RectTransform` `anchorMin`, `anchorMax`, `pivot`, `offsetMin` and `offsetMax`. The layer binder refuses an index outside the 32 layers Unity has with an error, because Unity keeps the previous layer for it silently. The parent binder keeps the local position — what a UI slot wants, so the item lands where the slot is — and treats a destroyed transform as `null` rather than parenting an object to something that no longer exists. The sibling index is clamped to the siblings that exist, so a ViewModel bound `OneWayToSource` is told where the object ended up. The five rect values are on the new Vector2 base and keep values a Vector3 base would have mangled: anchors outside 0..1 stretch an element past its parent and negative offsets push it over the edge, both of which are ordinary, so only a non-finite value is refused.
- **The rest of the text and input field properties.** Seven families: `TMP_Text` `fontStyle`, `enableAutoSizing`, `characterSpacing`, `lineSpacing` and `margin`; `TMP_InputField` `caretPosition` and `placeholder`. `fontStyle` travels as the whole flag set, because bold-and-italic is a combination rather than two binders. The two spacings keep negative values — tightening a title is what they are for — and refuse a non-finite one, which TMP would rebuild its mesh from and lose the text entirely; `margin` refuses a non-finite component for the same reason. `placeholder` is built on the object base, so a destroyed graphic cannot stay in the field as a live reference the next keystroke would touch. `caretPosition` is clamped to the text that actually exists, and says the thing that is easy to lose an afternoon to: a field keeps a caret position only while it is focused, so writing one to a field the user has not selected does nothing.
- **The rest of the collider domain, and the whole of 2D physics.** 3D colliders were the most densely covered corner of the package and still had gaps — the capsule had a radius binder and no height one — while `Collider2D` had nothing at all. Thirteen families: `CapsuleCollider` `height` and `direction`, `Collider` `contactOffset`, `includeLayers` and `excludeLayers`, `MeshCollider.cookingOptions`; and in 2D, `Collider2D` `isTrigger`, `offset`, `density` and `sharedMaterial`, plus `BoxCollider2D.size`, `CircleCollider2D.radius` and `CapsuleCollider2D.size`. The layer masks travel as an `int`, which is what `LayerMask` converts to and from. `contactOffset` is clamped to a small positive minimum rather than to zero, because Unity refuses zero and logs *"Contact offset must be greater than zero"* — its test found that. `Collider2D.density` says what Unity does not: the write is **ignored** unless the attached `Rigidbody2D` has Use Auto Mass on, silently and with nothing logged. The 2D material binder is built on the new object base, so a destroyed material arrives as `null` instead of as a reference the Inspector shows as `Missing`. `Collider2D.enabled` has no binder of its own on purpose: a `Collider2D` is a `Behaviour`, so the behaviour binders already take one.
- **Casters that parse a bound string.** The caster binders covered the direction *into* a string and not the one out of it — which is the direction an input field works in, so a ViewModel holding a number could be shown in a text field and not filled from one. `StringToIntCasterMonoBinder`, `StringToFloatCasterMonoBinder` and the abstract `StringToEnumCasterMonoBinder<TEnum>` now close it, each with a serializable twin. Parsing tries the user's own culture first, because a comma is a decimal separator in most of Europe, and the invariant form second, so a value produced by code — a save file, a network payload, `ToString()` without a culture — still parses in a comma-decimal locale. Group separators are deliberately refused: with them `"1,2,3"` parses to `123` silently, a typo turning into a number a hundred times larger. `NaN` and `Infinity` are refused too, though float parsing accepts both as words — a clamp downstream cannot stop either. A string that does not parse forwards a configurable fallback; the numeric casters do not log it by default, because while a user types most of what arrives is not yet a number, and an error per keystroke would bury the console.
- **Ready-made parameterized command binders for `Button`.** Every command binder that carries a parameter was abstract, because Unity cannot add a generic MonoBehaviour as a component — so "buy 10 of this", "load level 2", "equip that prefab" each needed a one-line C# subclass written before the Inspector would show anything. Five concrete closures now ship: `ButtonCommandInt`, `Float`, `String`, `Bool` and `ObjectMonoBinder`. They add nothing of their own: the parameter, the interactable modes and the `CanExecute` wiring all come from `ButtonCommandMonoBinder<T>`, which means the button's interactable state follows the command's answer *for that parameter* — a "buy 10" button is disabled by the same command that leaves "buy 1" enabled.
- **`AudioMixer` and `AudioListener` binders.** The package bound `AudioSource` thoroughly and the two things above it not at all, so a sound settings screen — the most common audio UI there is — had nothing to build on. `AudioMixerFloatMonoBinder` writes an exposed mixer parameter, which is one value for everything routed through the group instead of one binder per source that a runtime-spawned source escapes anyway; the write is reported when it fails, because `SetFloat` answers `false` for a name the mixer does not expose and does nothing else. `AudioMixerSnapshotMonoBinder` transitions to one of the snapshots listed in the Inspector, selected by index — what an enum-driven audio state sends — or by name. `AudioListenerVolumeMonoBinder` and `AudioListenerPauseMonoBinder` bind the two static properties: the master volume a project without a mixer has nothing else to bind a slider to, and the pause that silences every source while keeping its position, which `Time.timeScale = 0` does not do because audio ignores the time scale. Each has a serializable twin. Mixer values are written unchanged — a mixer volume is in decibels, so a linear slider needs a converter, and the binder does not guess at the parameter's range.
- **Canvas scaling and layout fitting binders.** Four components decide how a UI answers a screen it was not designed for, and none of them could be bound — while their immediate neighbours, `LayoutElement` and the horizontal and vertical layout groups, already could. Twelve families: `CanvasScaler` `uiScaleMode`, `scaleFactor`, `referenceResolution` and `matchWidthOrHeight`; `GridLayoutGroup` `cellSize`, `spacing`, `constraint` and `constraintCount`; both `ContentSizeFitter` axes; and `AspectRatioFitter` `aspectMode` and `aspectRatio`. `scaleFactor` is the UI-scale slider a settings screen offers, and the reason the scaler needed a binder at all: accessibility scaling is a ViewModel value, not an authored one. The guards follow what each property actually tolerates rather than one rule for all — the reference resolution is raised to at least one on both axes because the scaler divides the screen size by it, the grid's cell size is clamped non-negative while its spacing is not (overlapping cards are made with negative spacing), and the spacing and the aspect ratio refuse a non-finite value outright instead of clamping it, because one `NaN` puts a whole layout at `NaN`. `scaleFactor` uses the same `0.01` floor Unity applies in its own setter. `AspectRatioFitter.aspectRatio` carries the one non-obvious fact about it: while `aspectMode` is `None`, the fitter recomputes the ratio from the element's rect outside play mode, so a written value does not survive until a mode is set.
- **The properties their own domains had left out.** Six families, each the one thing a project would reach for and not find: `Scrollbar.size` — the fraction of the content the handle covers, which a scrollbar not driven by a `ScrollRect` has to set itself; `ScrollRect.normalizedPosition` — both axes at once, for restoring a remembered position or scrolling a grid back to a corner, on the new Vector2 base so the ViewModel is told a `Vector2` and not a `Vector3` with a zero it never held; `SpriteRenderer.size` — the size a tiled or sliced sprite is stretched to, where the alternative is scaling the transform and stretching a sliced border with it; `Rigidbody.constraints` and `Rigidbody2D.bodyType` — the two physics properties a ViewModel changes at runtime rather than authoring once; and the two `ParticleSystem` module values an effect is tuned by, `emission.rateOverTime` and `main.startColor`. The emission binder writes the module's *multiplier*, so a rate authored as a curve keeps its shape and is scaled rather than replaced. Every numeric one clamps: 0..1 for the scroll and scrollbar values, non-negative for the sprite size and the emission rate, with a non-finite value landing on the lower bound instead of reaching the component.
- **Property bases for `Vector2`, `Quaternion` and `UnityEngine.Object`.** The package had bases for `bool`, `int`, `float`, `string`, `Color` and `Vector3`, and nothing for the three types left. A two-dimensional property had to be bound through the Vector3 base, which reports `Vector3(x, y, 0)` back to the ViewModel in `OneWayToSource` — a value the property never held; a rotation property had to restate the Euler and scalar overloads in every binder; and an object-typed property had no base at all. `TargetVector2Binder<T>` / `ComponentVector2MonoBinder<T>` accept a `Vector3` by dropping its Z and broadcast a scalar to both components. `TargetQuaternionBinder<T>` / `ComponentQuaternionMonoBinder<T>` read `Vector2` and `Vector3` as Euler angles, apply a scalar as the same angle on all three axes, and refuse `TwoWay` in the base rather than leaving each binder to remember that a rotation raises no change event. `TargetObjectBinder<T, TObject>` / `ComponentObjectMonoBinder<T, TObject>` normalise a destroyed object to `null` in both directions: a destroyed Unity object is not a `null` reference, so without the check the ViewModel could hand over an asset the Inspector shows as `Missing`, or be told a destroyed one is live.
- **`ParticleSystem` binders — `Play`, `Stop`, `Pause`, `Clear` and `Emission Enabled`.** An effect is something a ViewModel starts — a hit, a pickup, a level-up — and nothing in the package could start one. The four operations follow the shape `AudioSourcePlaybackMonoBinder` already uses: each hands the ViewModel one operation, as a plain `Action` or as an `IRelayCommand` whose `CanExecute` reflects whether the system is there and its object active. `Emission Enabled` is the one that turns an effect off without ending it: the particles already alive keep going and it resumes with no restart, which is what a thruster or rain wants where `Stop` and `Play` would end and re-begin it.
- **Two-way binding for `TMP_Dropdown.value`.** A dropdown exists to be chosen from, and nothing carried that choice back: the binder could set the selection but never learn of one, so reading it took a second binder wired to the ViewModel by hand. `DropdownValueMonoBinder` now supports `TwoWay` alongside the modes it already had. A write goes through `SetValueWithoutNotify`, because assigning `value` raises `onValueChanged` exactly as a click does — the binder would read its own write back as a user choice, and so would any other binder on the same dropdown. When Unity refuses an index outside the options that exist, the ViewModel is told what the dropdown actually holds rather than being left believing in the index it sent. `ComponentIntMonoBinder<T>` gained a `protected RaiseNumberValueChanged`, so a binder that listens to its component can reach a `float` field in the ViewModel and not only an `int` one.
- **`TMP_Text` and `TMP_InputField` property binders.** Four families: `MaxVisibleCharacters`, `RichText`, `CharacterLimit` and `ReadOnly`. `maxVisibleCharacters` is the property behind a typewriter reveal and the only way to animate text without rebuilding the string every frame — the usual workaround, binding a growing substring, reflows the layout on every character. `richText` matters when the string comes from somewhere the game does not control and its markup should be shown rather than obeyed. Nothing is sanitised: Unity maps a negative character limit to `0` itself, and neither property has a non-finite case.
- **`Light` and `Camera` binders.** Lighting and cameras had no binders at all, so dimming a lamp or zooming a camera from the ViewModel meant reaching for the component by hand. Eight families: `Color`, `Intensity`, `Range` and `Spot Angle` on the light; `Field Of View`, `Orthographic Size`, `Background Color` and `Orthographic` on the camera. A probe against the raw components decided the sanitising policy: Unity clamps every range it cares about, but stores `NaN` verbatim in all of them and turns a non-finite `Light.range` into zero, which switches the lamp off. So the numeric binders drop a non-finite write and clamp nothing else — a negative orthographic size mirrors the view rather than being invalid, and is passed through.
- **`Rigidbody` and `Rigidbody2D` binders.** Physics had no binders at all, while every collider was covered. Six families: `Mass`, `Use Gravity` and `Is Kinematic` in 3D, `Mass`, `Gravity Scale` and `Simulated` in 2D. Both mass binders drop a non-finite value instead of writing it, because the two bodies disagree about it on their own: `Rigidbody` stores `NaN` in silence and then quietly leaves the simulation, while `Rigidbody2D` refuses it and logs an error naming the object. Dropping the write in both keeps the pair behaving alike. The range needs no guard — Unity clamps zero, negatives and infinities to a legal mass itself. `Gravity Scale` is not clamped either: `0` suspends gravity and a negative value inverts it.
- **`LayoutElement` and `Canvas` binders.** A `LayoutElement` is how one child overrides what its layout group would otherwise decide, and none of its numbers could be bound — so a ViewModel could not widen a panel or take an element out of the flow. `Canvas.sortingOrder` had none either, which is what brings a panel to the front. Seven families: preferred and flexible width and height, `Ignore Layout`, `Sorting Order` and `Override Sorting`. A negative preferred size means "no preference" to Unity and is passed through rather than clamped; `overrideSorting` only means something on a nested canvas, which its documentation now says.
- **`ScrollRect` position and axis binders.** The domain had Command and OneWayToSource binders only, so scrolling a list to the top from the ViewModel — the usual reason to reach for a ScrollRect — had no binder, and neither did locking an axis. Four families: `Vertical Scroll`, `Horizontal Scroll`, `Horizontal Enabled` and `Vertical Enabled`, each with the serializable binder, the `MonoBinder`, and the `Enum` and `EnumGroup` variants. Scroll positions are clamped to 0..1 through `BinderMath.SafeClamp01`, so a non-finite value cannot leave the content nowhere.
- **AudioSource playback binders — `Play`, `Stop`, `Pause` and `UnPause`.** The package bound every AudioSource *property* and none of its *operations*, so a ViewModel could set the volume of a sound it had no way to start. Each hands the ViewModel one operation, as a plain `Action` or as an `IRelayCommand` whose `CanExecute` reflects whether the source is there and its object is active — the same shape `AnimatorSetTriggerMonoBinder` uses for animation. A clip is deliberately not required: `Stop` and `Pause` are meaningful without one.
- **`Enum` and `EnumGroup` binders for `Toggle.isOn`.** The Toggle domain had only the plain binder, so the common shape — one enum in the ViewModel selecting one toggle out of a set of tabs or modes — had to be written as several boolean fields kept in step by hand. `ToggleIsOnEnumGroupMonoBinder` does it in one binder. Both write through `SetIsOnWithoutNotify`, because a programmatic write raises `onValueChanged` exactly like a click and any other binder on the same toggle would read it as user input. There is no `Switcher` variant: for a boolean the base class's two `SetValue` overloads collide, and the behaviour it would provide — inversion — is already the `IsOn` binder's own option.
- **A `SpriteRenderer` domain.** The package covered uGUI thoroughly and 2D not at all: a sprite renderer had no binder for its sprite, its tint, its facing, or its draw order. Flipping a character meant binding a negative scale, and tinting one meant going through the shared material. Five families — `Sprite`, `Color`, `Flip X`, `Flip Y` and `Sorting Order` — each with the serializable binder, the `MonoBinder`, and the `Enum` and `EnumGroup` variants.
- **Binders for the flags that decide whether a component participates.** `Graphic.raycastTarget` — the usual way to let clicks pass through an overlay — and `MaskableGraphic.maskable` had no binder at all. `Renderer.enabled` had none either: a `Renderer` is a `Component` and not a `Behaviour`, so the behaviour binders cannot take one. Three families, each with the serializable binder, the `MonoBinder`, and the `Enum` and `EnumGroup` variants.
- **`Scrollbar.value` binders.** The Scrollbar domain shipped only Command and OneWayToSource binders, so the one property a scrollbar exists for could not be bound at all — while `Slider` had the full matrix. Five new types mirror it: `ScrollbarValueBinder` and `ScrollbarValueMonoBinder` (both `TwoWay` and `OneWayToSource`, both accepting `int`, `long`, `float` and `double`), plus the `Switcher`, `Enum` and `EnumGroup` variants. A scrollbar has no configurable range — its value is always normalised to 0..1 — so the clamp is fixed rather than read from the component, and a clamped value is reported back to the ViewModel the same way the slider binders now do.

### Changed

- Six copies of the shader-property id cache are now one struct. `ShaderPropertyId` holds the `int?` and the resolve-once line the renderer colour binders each carried, and re-resolves when the name changes, which the Inspector allows at any time. The name itself stays where it is — a serialized field on each binder. Moving it into the struct would move it inside nested serialized data and lose the value every project had set, which is exactly the failure the converter rename in this package had to be reverted for.
- **The five `UnityGeneric*` binders, `BindMode.IsNone()` and `ThrowExceptionIfOne()` are `[Obsolete]`.** The audit asked for them to be removed; they are deprecated first, with the replacement named in the message, because they are public API a project may already be compiling against. The `UnityGeneric*` copies differ from the `Generic*` ones only in taking a `UnityAction` where the others take an `Action` — and a `UnityAction` converts to an `Action` implicitly, so the copies buy nothing. `IsNone` reads as a question about validity and is a comparison with one enum member. `ThrowExceptionIfOne` has no caller: a binder that supports only the reverse direction uses `ThrowExceptionIfNotTwo`, and one that supports only the forward direction has nothing to reject.
- `TransformRotationBinder` and `TransformRotationMonoBinder` derive from the new Quaternion bases instead of restating the four numeric `SetValue` overloads and the `IRotationBinder` / `INumberBinder` list themselves. Behaviour is unchanged — the members they used to declare are pinned by tests — and the serialized fields are untouched, so no scene or prefab data moves.
- **`Aspid.MVVM Settings`** window restyled to match the Aspid.FastTools **Welcome** window — animated dot background, animated logo (links to the Asset Store) and title, themed cards, gradient `Apply` / `Revert` buttons and a footer with version and links.
- Moved the settings window into the shared `Tools/Aspid 🐍` top-menu submenu, next to `Welcome FastTools`.
- Settings window version is now read from the package manifest instead of a hard-coded constant; `AspidToggle` colors aligned with the theme.
- `[SerializeReference]` fields in the `MonoView` / `MonoViewModel` / `MonoBinder` inspectors are now drawn with the FastTools type-picker dropdown instead of Unity's default managed-reference UI. The inspectors route them through `SerializeReferenceEditorGUI`, so no `[TypeSelector]` attribute is needed on any field and the candidate set is the field's own declared type. Nested managed references *inside* an assigned instance keep Unity's default UI — FastTools draws an instance's own children with a plain `PropertyField`.
- `Aspid.FastTools` is no longer embedded under `Packages/`. It is consumed as a UPM git dependency pinned to the immutable per-release tag `upm-preview/1.0.0-rc.7`, up from the embedded `1.0.0-rc.4`. rc.6 brought `[TypeSelector]` support for `[SerializeReference]` fields — the replacement for the removed `SerializeReferenceDropdown` integration — and rc.7 adds three type-picker fixes this project depends on: a candidate the field cannot close is no longer offered, generic arguments are inferred through the field's interfaces, and Unity's built-in types are accepted as generic arguments. Two upstream API renames were followed: the `Aspid.FastTools.Reflection` namespace collapsed into `Aspid.FastTools`, and `SerializedProperty.GetClassInstance()` became `GetDeclaringInstance()`.
- `GenericToString<TFrom>` exposes formatting as a virtual `Format` hook instead of hard-coding the decision in `Convert`. An empty format now falls back to `ToString()` rather than producing an empty string, and `Format` still receives the typed value, so numeric and date specifiers (`{0:F2}`, `{0:hh\:mm}`) keep working. `formatEmptyValues` moved down to `StringFormatConverter`, the only converter with an opinion about blank input; `ObjectToStringConverter` and `TimeSpanToStringConverter` gained the format constructor they were missing.
- Inspector attributes (`[SerializeField]`, `[SerializeReference]`, `[Tooltip]`) in the Unity-independent layers are no longer wrapped in `#if UNITY_2022_1_OR_NEWER`. No-op stubs in `Source/Compatibility/UnityAttributesShim.cs` stand in for them outside Unity, so 22 preprocessor blocks across 14 files could be dropped. Directives guarding real Unity API (`Debug`, `Component`, `ProfilerMarker`) are unchanged.

### Fixed

- Twelve copies of the same converter bridge are now one pair of helpers. A `[SerializeReference]` field could not be typed on a generic interface until Unity 2023.1, so every binder with a converter declares its field as a non-generic alias on older versions and as the generic interface on newer ones — and each carried its own four-line `#if` to convert a constructor argument into whichever the field is. `ConverterBridge` and `ConverterBridgeUnity` hold it once per assembly; on 2023.1 and newer every method is the identity.
- The binder inspector no longer throws while it is being torn down. `MonoBinderEditor.OnDisable` raised a `NullReferenceException` when the binder's View was not a `MonoView` — from `OnDisable`, where an exception breaks the teardown, and named after a local variable rather than the reason. A View of another type is now left alone with a warning that says which type it was: the id-sync validation only knows how to check a `MonoView`.
- The sizeDelta binders now report a `Vector2` as well. A rect's size is two numbers, and the family is built on the Vector3 base, so in `OneWayToSource` it reported `Vector3(width, height, 0)` — a value the property never held, and one a ViewModel field of type `Vector2` could not receive at all. Both channels are raised, so a ViewModel binds whichever type it holds. The second channel is an explicit interface implementation on purpose: the base already publishes an `IReverseBinder<Vector3>` event of the same name, and interface mapping prefers the inherited member — the same rule that silenced the numeric binders' reverse channel until it was fixed.
- The `BindMode` dropdown kept the user's choice only for a rebindable owner. The write sat behind an `is IRebindableBinder` check, so picking a mode on a serializable binder inside a View — or on any plain `[BindMode]` field — did nothing at all and the dropdown snapped back on the next repaint. The write now happens first and unconditionally, and the rebind happens after it when the owner supports one. Three more things in the same drawer: it no longer writes serialized data while Unity is laying the object out (correcting a mode the class forbids is deferred to the next editor tick, because a write from inside a drawer is lost on a repaint, dirties a scene from a redraw alone and cannot be undone); it passes the field's label through instead of drawing every `BindMode` field nameless; and it shows a mixed value for a multi-selection rather than the first object's mode. Its cache of the owning class is now keyed on the instance — Unity reuses one drawer for every element of a list and every object in a selection, so the old "already looked" flag handed the second binder the first one's allowed modes.
- The debug binders no longer build their log strings in a release build. `DebugLogBinder` and `DebugLogMonoBinder` route every message through a helper marked `[Conditional("UNITY_EDITOR")]` and `[Conditional("DEVELOPMENT_BUILD")]`, so the compiler removes the call and the interpolated string with it. The binders themselves still compile into every build on purpose: a component compiled out takes every scene reference to it with it.
- The Editor types an integration would touch are documented. Ten public types under `Aspid.MVVM` had none at all — the id and view Inspector properties, the drop-target row, the three composite fields, and the two data structs behind the dropdowns. Two of them keep behaviour that the code does not make obvious: `CompatibleBinderWithField` is compared with `Max()`, so the order its members are declared in decides which binder a multi-object drag picks, and `BinderViewData.GetViewName` throws when the view it is given is not one. Both now say so.
- Documentation hygiene, mostly about links that were not links. 77 places printed a name in monospace where the documentation could point at the actual member — `CanExecute`, `CanExecuteChanged`, `SetTrigger`, the `TBoxed` type parameter, and the `null`/`true`/`false` keywords. Monospace text does not navigate, does not survive a rename, and does not distinguish the keyword `null` from the word. 17 single-line `<summary>` blocks were expanded to the multiline form the package's own convention requires. And 13 example names in four command binder families used a `T1T2` scheme where the rest of the package uses the documented `{2}`, renamed in the `<include>` and the XML together.
- The convention's own example was wrong. `references/tags.md` showed `AudioSourceVolumeBinder`'s constructor as the model pass-through case for `<inheritdoc/>`, but that constructor rejects `TwoWay` — it is exactly the case that needs its own documentation. Replaced with a constructor that really is pass-through, and the counter-example is now named as such.
- The binder lifecycle now says what order its hooks run in. Nothing did, and the order is the whole reason `OnBound` is where a binder subscribes to its component: the ViewModel's first value arrives *after* `OnBinding` and *before* `IsBound` becomes true, so a subscription taken in `OnBinding` hears that first value come back as if the user had entered it. Both `Binder` and `MonoBinder` now describe the sequence and say which hook is for what.
- Two `<inheritdoc/>` blocks that inherited the wrong thing. `GetConvertedValue` on the boolean binders inherits "returns the value unchanged by default", which stops being true the moment the Invert option is set. `ImageSpriteBinder.OnUnbound` **destroys** the sprite it created — the one fact about that method worth knowing, and it was inherited away.
- Members with a hand-written summary now document their parameters too. 451 of them across the package had a summary somebody wrote by hand and not one `<param>` under it — 494 parameters in total, almost all of them the value arriving from the ViewModel or the component an enum group is writing to. The compiler is silent about this on purpose: `CS1573` fires only when *some* parameters are documented, treating a member with none as a deliberate choice. A contract test now treats it as the omission it was, exempting members that inherit their documentation.
- Every serialized field a user configures now has a tooltip. 95 of the 495 fields across the binders and converters had nothing to hover over — including every `_converter` slot on the UnityEvent binders, every `_param` on the command ones, and every `_interactableMode`. The Inspector shows a field by its name alone: no type, no units, no range, and no hint that leaving it empty is allowed. A contract test keeps it that way; the binder's own bookkeeping and anything marked `[HideInInspector]` are exempt, because a user never sees them.
- A binder that refuses to construct now says so. 155 of the 172 places that validate a binding mode threw without documenting it, so a caller reading the documentation could not tell whether an unsupported mode would be ignored or would throw. The two guard families raise different types — `ThrowExceptionIfTwo` and its relatives raise `InvalidOperationException`, `ThrowExceptionIfMatches` and `ThrowExceptionIfNone` raise `ArgumentException` — and each site now names the one it actually raises and the condition that triggers it. A contract test keeps it that way.
- Documentation that described behaviour the code does not have. Eight `ToSource` binders said they send "the current bound property value" — they send the **component reference**; that is the whole point of the family, and 23 of their siblings said so correctly. `SphereColliderCenterMonoBinder` documented `BoxCollider.center`. The `AudioSource` min/max distance binders claimed to set both endpoints, when `AudioSourceDistanceMode` selects which one is written and only `Range` writes both. `InputFieldBinder` listed three binding modes where it accepts all four. `AddBinderContextMenuAttribute` promised to "automatically populate serialized properties", which nothing does — the names decide where the menu entry appears, nothing more — and its `Path`/`SubPath` are set on many binders but read by no code, now documented as unimplemented rather than left looking functional. The `ByBind` binders' `Invert` tooltip described inverting a bound value; those binders ignore the value entirely and follow whether a binding exists.
- Ten overridden lifecycle hooks carried no documentation at all, while their twins two folders away were documented in full — an undocumented hook answers neither of the questions its next reader has, which is when it runs and whether an override must call the base. Documented, and a contract test now keeps them that way.
- The XML documentation now actually resolves. Unity compiles without `-doc`, so every broken documentation reference in the package was invisible — and 348 of them had accumulated: 193 crefs the compiler cannot parse, 96 comments that are not well-formed XML, 32 ambiguous references, 9 that name a member the type does not have. Nothing rendered for any of them. The common causes were generic arguments written with angle brackets instead of braces (invalid XML), and keywords or nested types used as generic arguments in a cref (`IRelayCommand{int}`), which the language does not allow; those now reference the open generic and show the concrete form as link text — the shape `EventTriggerCommandBinder` already used. Also: `SpriteRenderer.sortingOrder` is declared on `Renderer`, `IReadOnlyObservableList{T}.CollectionChanged` on `IObservableCollection{T}`, and `Quaternion.Euler` needed its overload naming. All four package assemblies now build clean with `-doc`.
- Four `<include>` paths in `SliderCommandMonoBinder` pointed at a file one directory up and never resolved, and 21 `<member>` examples across eight XML files described MonoBehaviour binders, which by the package's own convention carry no examples — written, maintained and rendered nowhere. Removed, and a contract test now checks that every include resolves, names a member that exists, and that no example sits unreferenced.
- Thirty binders sat in a different branch of the Add Component menu from their siblings, separating the component name from the property with a hyphen where the other 347 used an en dash. Normalised, and a contract test now pins both that and the `Aspid/MVVM/Binders` prefix. Both contract tests assert they actually swept the package, so a wrong base type or assembly filter cannot make an empty sweep read as a clean one.
- The `AudioSource.Priority` binders are now offered when you right-click that property. The Switcher variant named the serialized property `m_Priority`, which `AudioSource` does not have — it serialises `Priority` — and the other three variants named nothing at all, so the whole family was unreachable from the property's context menu. A new contract test walks every `AddBinderContextMenu` in the package and fails if a name does not match a serialized property on the target component, at any depth; nothing guarded these names before, and a wrong one fails in silence.
- `NaN` and infinities no longer slip past a clamp into the component. `Mathf.Clamp` and `Mathf.Clamp01` are written as comparisons, and every comparison against `NaN` is false, so a non-finite value passed through all 48 clamped binder sites untouched — into `alpha`, `fillAmount`, `pitch`, `spatialBlend`, `panStereo` and the rest. A ViewModel only has to divide by zero once to produce one, and the symptom surfaces later and elsewhere: a handle that will not move, a graphic that vanishes. The new `BinderMath.SafeClamp` / `SafeClamp01` map non-finite input to the lower bound and to `0`. The six integer `priority` binders are untouched — `int` cannot be `NaN`.
- The renderer colour binders no longer instantiate a material just to read a colour, and no longer allocate an array per value. `Renderer.material` and `Renderer.materials` both instantiate on read — Unity says so itself in the editor: *"Instantiating material due to calling renderer.material during edit mode. This will leak materials into the scene."* The two getters now read `sharedMaterial`, which answers the same question without replacing the asset. The write path still uses `materials`, because writing to the shared asset would recolour every object using it, but fetches the array once and clears it on unbind — the pattern the switcher variant of this same family already used. The `EnumGroup` variant is left alone: it receives a different renderer on every call, so a single cached array would be wrong.
- A behaviour binder no longer resolves itself as its own target. The three binders typed on `Behaviour` fell back to `GetComponent<Behaviour>`, which matches every behaviour on the object — binders included — with component order deciding the winner. On an object carrying little else that is the binder itself, which then enabled and disabled itself, stopped receiving values, and left nothing in the log to explain it. The fallback now skips binders; `ComponentMonoBinder` exposes it as `ResolveComponent` so a binder typed on a base class can narrow the search.
- `SelectableColorBlockSwitcherBinder` is no longer compiled out on Unity 2022 without TextMeshPro. It was wrapped in the TMP integration guard, which only the InputField binders have anything to do with — every other member of its family, and the `ColorBlock` converter interface itself, compile unconditionally.
- The localization entry binders no longer hand the ViewModel a silent `null`. `TableEntryReference` converts to `string` through its `Key`, which is filled only for an entry referenced *by name* — and picking one through the Localization inspector stores it by id, which is the common case. In `BindMode.OneWayToSource` the four entry getters passed the resulting `null` on as if it were the entry. Resolving an id to a name needs the shared table data loaded, which a binder cannot assume, so the value is still `null`; what changed is that the binder now says why, naming itself and the id.
- A slider value the control cannot hold is now reported back to the ViewModel. Unity clamps a value outside `[minValue, maxValue]` inside `Slider.Set` and raises `onValueChanged` for it — but the binder suppresses that event with the echo guard around its own assignment, so the corrected value never arrived and, in `TwoWay` or `OneWayToSource`, the two stayed apart until the ViewModel changed the property on its own. The value is now clamped before the write and the reverse channel is told whenever the clamp actually changed it. A converter's own effect is still not reported back — only the difference the clamp made. `NaN` is stopped as well, through `BinderMath.SafeClamp`.
- The input field binders no longer subscribe to the field from `OnValidate` while unbound. That callback re-wires the subscriptions after the bind mode is changed in the inspector during play mode, but it did so without checking whether the binder was bound — and `Unbind` returns immediately when it is not, so `OnUnbound`, and with it the unsubscribe, never ran: the listener stayed on the field with nothing left to remove it. Repeating the inspector edit stacked duplicates as well, since `UnityEvent` accepts the same listener more than once, and every user keystroke then reached the ViewModel twice. Five arities across the text and command binders.
- A `*MonoBinder` on a GameObject that has no component for it to drive now refuses to bind. `MonoBinder.IsBind` returned `true` unconditionally and no component binder overrode it, so binding succeeded and the first value threw from inside a leaf class's property setter — a message naming neither the binder nor the GameObject. `ComponentMonoBinder` now answers `IsBind` from the resolved component, which is the guard the serializable `TargetBinder` has had all along.
- Turning off "disabled when null" no longer force-enables the component. All 14 sprite and texture binders wrote `enabled = !_disabledWhenNull || value`, which is unconditionally `true` once the option is off — so instead of leaving the component alone, the binder switched it on again on every value. The option now guards the assignment. The serializable variants default the option to `false`, so a binder configured in a `MonoView` hit this on every update.
- `GraphicMaterialBinder` and `GraphicMaterialSwitcherBinder` can now be constructed for any `Graphic`. Both are declared for `Graphic` but their only constructor took a `RawImage`, so an `Image` or a `Text` could not be bound from code at all. The XML docs said `RawImage` too.
- Removed the `NotImplementedException` override in `SwitcherFloatBinder`. It suppressed the compiler's demand that subclasses implement `SetValue`, and was unreachable — all 16 shipped subclasses override it. Deleting it restores the compile-time check and matches `SwitcherIntBinder`.
- An integer Animator parameter now changes when the value changes by one. Both int binders compared the incoming value with the current one through `Mathf.Approximately`, whose tolerance is *relative*: past roughly a million it exceeds 1, so a change of one counted as no change and the write was skipped; past 2^24 the two operands are indistinguishable as `float` at all, and the parameter could never update again. They now compare as integers.
- `OnEnable` no longer resets an Animator parameter to zero. It re-applied the stored value unconditionally, and that value starts at `default(T)` — so enabling a binder before it had received anything wrote a zero over whatever the ViewModel had set, without telling it. Re-applying now waits until a value has actually arrived, and both reverse paths record the value they push, so the restored state is what the ViewModel last asked for.
- `TwoWayValue<T>` no longer feeds a ViewModel update straight back to the ViewModel. `IBinder<T>.SetValue` assigned through the `Value` property, whose setter is the View-side entry point and raises the reverse channel — so every update travelling ViewModel → View turned around immediately and travelled back, carrying the **converted** value. The model was overwritten with what the display shows, and a converter that is not idempotent kept going until the generated setter's equality check happened to stop it. `SetValue` now writes the backing field; setting `Value` from the View still notifies as before.
- The converter overload of `OneWayToSourceValue<T>` is marked `[Obsolete]`. The inherited converter is applied on the ViewModel → View path, which this mode does not have, so one passed here was silently ignored and values reached the ViewModel unchanged. The overload still compiles — it now warns instead of doing nothing quietly.
- The binders that accept any bound type no longer throw on a `null` value. `UnityEventStringMonoBinder.SetValue<T>` called `value.ToString()` and both debug log binders dereferenced the value to format it. That path — `IAnyBinder` — is the one taken whenever a binder has no overload for the member's own type, which is every reference type other than the ones spelled out, and a bindable member of such a type publishes `null` the moment the binder is added. So `null` was the first thing these binders saw, not an edge case. The event now forwards an empty string and the log prints `null`.
- `new DebugLogBinder()` now gets the default converter its own documentation promises. The constructor assigned its parameter straight over the field initializer, so the parameterless call left the binder with no converter at all — the opposite of "pass `null` to use `ObjectToStringConverter`".
- The collider material binders no longer replace the assigned asset with a clone just by reading it. `Collider.material` is an instancing property: reading it makes Unity swap in a private copy named `"… (Instance)"` and keep it until the collider is destroyed. Both binders read it in `BindMode.OneWayToSource`, so the ViewModel received a clone that no longer compared equal to the asset it had handed over — `material == iceAsset` was false — and every distinct collider bound this way left one behind. The two getters now read `sharedMaterial`. The setters are unchanged: assigning does not clone, and assigning `sharedMaterial` would edit the asset for every other collider using it.
- A binder whose serialized target has been destroyed now refuses to bind instead of throwing from `OnBound`. The constructor's `ArgumentNullException` guard never runs for a serialized instance — Unity assigns `Target` directly — and the only protection was `IsBind => Target is not null` in 25 command binders, written with C#'s null check, which a destroyed `UnityEngine.Object` passes: the managed wrapper outlives the native object. Every other `TargetBinder` descendant had no protection at all. The check now lives in `TargetBinder` itself and uses Unity's own conversion, so all of them get it, and the 25 hand-written overrides are gone.
- A destroyed `MonoBinder` in a View's array is now treated as an empty slot. `BindSafely` and `UnbindSafely` tested each element with `is null`, so a binder destroyed independently of its View was handed to `Bind`, which threw `MissingReferenceException` from the first Unity API it touched. The same three-line check now covers both cases.
- 89 constructor docs across 23 files no longer understate their `BindMode` constraint. They promised only that `BindMode.TwoWay` was refused, while the guard they run — `ThrowExceptionIfTwo` — rejects `BindMode.OneWayToSource` as well, because `IsTwo()` covers both. Anyone following the documentation would pick `OneWayToSource` for a reverse binding and get an exception the docs said could not happen. The wording now names both modes, and a test walks the inheritance graph and fails if the two ever diverge again.
- `UnityGenericOneWayBinder` now validates its bind mode, as its own documentation already claimed. Its non-Unity twin `GenericOneWayBinder` calls `ThrowExceptionIfTwo`; the Unity variant called nothing, so a `TwoWay` or `OneWayToSource` mode was accepted and then failed later and less clearly, at the bindable member that could not find a reverse binder. Its constructors were also `protected` while the twin's are `public`, which left a public, non-abstract class that no consumer could instantiate; both are now `public`.
- Collider extents and `AudioSource.timeSamples` are no longer written out of range. Unity refuses a non-finite collider extent on its own, but stores a negative `BoxCollider.size` or `SphereCollider`/`CapsuleCollider.radius` silently and leaves the physics engine with inverted geometry; those are now raised to `0` through the new `BinderMath.NonNegative`. `AudioSource.timeSamples` likewise stores a negative position or one past the end of the clip, and `AudioSource.time` refuses such a seek — but refuses it loudly, with an audio-engine error per assignment, leaving the playhead where it was. Bound to a seek slider or a `progress * duration` calculation with a stale duration, that is an error per frame while the control appears not to work. Both playback properties now clamp to the current clip, and skip the write when no clip is assigned. 30 sites across the Collider, Time and TimeSamples families.
- A binder whose target component reference is empty or broken now falls back to `GetComponent`, as its documentation always promised. `ComponentMonoBinder.CachedComponent` tested the serialized field with `is not null`, but an unassigned or dangling Unity object reference reaches managed code as a wrapper that is not `null` to C# while pointing at nothing — so the fallback was skipped and every caller received a component it could not use. Delete the target component and the binder went dead instead of re-resolving; `OnValidate` had the same test, so the inspector never healed it either. Both now decide with Unity's own conversion. This sits under every `*MonoBinder` in the framework.
- `EnumGroup` binders no longer throw on an entry whose element is unassigned. `SetValue` walked the table and dereferenced each element, so one empty slot — an ordinary state while editing the table — raised a `NullReferenceException` from inside the loop and the entries after it never received their value, leaving the group in a mixed state. Empty entries are now skipped, naming the enum key once per binder, and the rest of the group is still updated. This is one change in the shared base, so all 71 `EnumGroup` binders get it.
- Animator binders no longer address a parameter their controller does not have. The name is serialized and nothing checked it, so a typo or an empty field produced a Unity error on every single assignment — 60 a second in the editor for a value that changes per frame, and complete silence in a build with the animation simply not moving. The binders now verify the name and the parameter type once per controller, refuse the assignment and report it once. Two paths that skipped the check entirely were closed at the same time: `OnEnable`, which re-applied the last value directly, and the plain `Action` handed to the ViewModel in `OneWayToSource`, which bypassed `CanExecute` while the `IRelayCommand` path honoured it.
- A command binder set to `InteractableMode.Custom` with no `ICanExecuteView` assigned now reports the misconfiguration instead of throwing. The programmatic path was guarded — the constructor rejects a null view and refuses `Custom` without one — but `_interactableMode` and `_customInteractable` are serialized, so the inspector let the mode be chosen with the reference left empty, and the first `CanExecuteChanged` threw a `NullReferenceException` naming neither the binder nor the object. Because the throw happened inside a `CanExecuteChanged` handler, it also cut the notification short for every other subscriber of that command.
- `InteractableMode.Visible` on the `*CommandMonoBinder` variants now hides the control it was pointed at rather than the binder's own GameObject. The branch called `gameObject.SetActive` while the serializable twins used `Target.gameObject`; since the target `Selectable` is a serialized field that may live on any object, a binder placed beside its control hid itself and left the control visible and clickable. The `Interactable` branch in the same switch already used `CachedComponent`.
- All 50 of those switches — 12 files across Buttons, Toggles, Sliders, Scrollbars, Dropdowns and InputFields — were replaced by one `Selectable.SetInteractable` extension, which also names the binder when the target `Selectable` itself is missing or destroyed.
- A slider or audio source can no longer be left with its range inverted. `SetMinMax` and `SetMinMaxDistance` assigned the two endpoints in order, and neither Unity property enforces `min <= max`, so a `Vector2` arriving as `(10, 2)` — or a `Min`/`Max` mode update crossing the endpoint already on the component — produced a slider whose `normalizedValue` reads backwards and an audio source silent at every distance. Both now swap a crossed pair and log which one they saw; a non-finite endpoint is refused outright rather than written. Distances are additionally floored at `0`.
- `AudioSource.dopplerLevel` binders no longer pass `NaN` to the component. All six were missed by the clamp audit above because they had no clamp to convert: Unity enforces the 0..5 range inside the property setter, which hid that it lets a non-finite value straight through, corrupting the doppler effect for the whole source. They now route through `BinderMath.SafeClamp`.
- One failing binder no longer takes the rest of the collection with it. `BindSafely` and `UnbindSafely` were safe only with respect to `null` elements — the loop called into each binder unguarded, so the first exception abandoned every binder after it. On bind that left the View half-initialised; on unbind, which `MonoView.OnDestroy` drives, it left the remaining binders subscribed to a ViewModel that was going away. Each loop now reports the failure with the owner, member name and index, and carries on.
- Replacing a dropdown's options no longer leaves a stale caption. The `IEnumerable<OptionData>` overloads of both dropdown options binders mutated `TMP_Dropdown.options` directly, bypassing the `RefreshShownValue` that `AddOptions` and `ClearOptions` perform — the MonoBinder showed an empty caption and the serializable twin kept showing the previous set's text.
- The dropdown's selected index now survives an options update. `ClearOptions` resets it to 0 (or -1 with a placeholder) and raises nothing, so a ViewModel holding the previous index silently disagreed with the control after every refresh. The selection is now restored, clamped to the new list, without a notification.
- The View → ViewModel channel of the Toggle, Slider and InputField binders no longer goes permanently silent after an exception. Each suppresses its own echo by clearing a flag around the assignment — the component raises `onValueChanged` synchronously and the binder must not read its own write as user input — but the flag was restored without `try`/`finally`. An exception from any other listener on that event, or from a converter, left it cleared for good: the binder went on applying values yet never reported a single user edit again, with nothing in the log to explain it. All six sites are now wrapped.
- `CollectionMonoBinder<T>` now tracks the collection it is bound to. It applied the contents once at `SetValue` and never subscribed to `CollectionChanged`, so the View stopped following the list the moment it was bound — adds and removes simply did not show. Its serializable twin `CollectionBinderBase<T>` had subscribed from the start. Change notifications rebuild the View; `OnUnbound` unsubscribes.
- `CollectionViewModelMonoBinder<T>` no longer runs past the end of its serialized view array when the bound collection holds more items than there are views. The bounds check its serializable twin already had was missing.
- A view inserted anywhere but the end of an observable list now takes the matching sibling index. The factory parents each new object last in the hierarchy, so the visual order — and any LayoutGroup driven by it — drifted away from the model. `OnMove` in the same helper already did this.
- A binder added through the inspector now starts in a mode its own `[BindModeOverride]` allows. The serialized `_mode` began at `BindMode.TwoWay`, which the field's own `[BindMode(OneWay, OneTime)]` forbids, so an ordinary binder added and left alone was rejected by the bindable member it pointed at. The default is now per-type: `MonoBinder` exposes a virtual `DefaultMode` and applies it from Unity's `Reset` callback. No single constant would do — the 30 `*ToSourceMonoBinder` types allow only `OneWayToSource` and two `*ByBindMonoBinder` types only `OneTime`, so flipping the constant to `OneWay` would merely move the breakage. Binders created with `AddComponent` at runtime still get the raw field initializer.
- A destroyed `MonoBinder` now unbinds itself. `MonoBinder` had no `OnDestroy`, so a binder removed independently of its View — pooling, or a `Destroy` on a child object — stayed subscribed to the bindable member: the ViewModel kept a managed reference to a dead `MonoBehaviour` and kept calling it, so a destroyed binder went on writing to its target. Unbinding is now driven from `OnDestroy`; override it and call `base.OnDestroy()` to keep that behaviour. `CommandMonoBinder` needed no separate change — its `OnUnbound` already releases the command.
- `Renderer` material binders no longer throw when the material set is empty or null. `SetMaterials` assigned `renderer.materials = null`, which Unity rejects with `ArgumentNullException` from `SetMaterialArray`; an untouched `Material[]` field in the inspector is exactly that case, so the binder failed on its first value. The single-material branch now assigns a one-element array instead of clearing first.
- `LineRenderer` color binders no longer throw on their own default. `GetColor` rejected `LineRendererColorMode.StartAndEnd` — the MonoBinder's default — and `BindMode.OneWayToSource` reads the property back the moment binding is established, so the View's initialization aborted before the ViewModel saw a value. That mode keeps both endpoints in step, so the start color is now returned.
- `TextFontSwitcherBinder` and `DropdownOptionsSwitcherBinder` are marked `[Serializable]`. Unity does not inherit the flag from a base class, so both were invisible in the inspector and arrived at `Bind` as `null` fields — the binding silently did nothing. Their 53 siblings were marked.
- `SliderCommandBinder` now accepts `IRelayCommand<int>`, `IRelayCommand<long>` and `IRelayCommand<double>`. All four arities declared only `IBinder<IRelayCommand<float>>` while exposing `SetValue` overloads for the other three numeric types, so binding a non-float command threw `BinderInvalidCastException` and the whole View failed to initialise. `ScrollbarCommandBinder` already declared all four interfaces.
- `SetValue(Vector3)` called directly on a Vector3 binder no longer drops the Z component. `ComponentVector3MonoBinder<TComponent>` and `TargetVector3Binder<TTarget>` declared `SetValue(Vector2)` while inheriting `SetValue(Vector3)` from their base; C# builds the overload candidate set from the most derived type that declares an applicable member and looks no further, and `Vector3` converts implicitly to `Vector2`, so the 2D overload won and Z was silently zeroed. Both classes now redeclare `SetValue(Vector3)`. Binding through a ViewModel was never affected — it dispatches via `IBinder<Vector3>`, whose interface map points at the base method.
- Ten Transform binders now write to the component assigned in the inspector instead of the binder's own `transform`. `TransformScaleMonoBinder`, `TransformRotationMonoBinder` and the `Switcher` / `Enum` variants of Scale, Position, EulerAngles and Rotation dereferenced the inherited `Component.transform`, so a binder pointed at a child moved, scaled or rotated its own GameObject and — in `BindMode.OneWayToSource` — reported its own value back to the ViewModel. Their siblings in the same families already used `CachedComponent`.
- `BindMode.OneWayToSource` now reaches the ViewModel for the numeric binders' own type. `TargetFloatBinder` / `ComponentFloatMonoBinder` publish `float`, and `TargetIntBinder` / `ComponentIntMonoBinder` publish `int`, through the `ValueChanged` event inherited from `TargetBinder<TTarget, TProperty>` / `ComponentMonoBinder<TComponent, TProperty>`: a class member wins over a default interface implementation, so the bridge `INumberReverseBinder` declares for that instantiation never applied, and `OnBound` did not chain to `base.OnBound()`. A ViewModel field of the binder's own numeric type silently kept its default value while the other three numeric types worked — retyping the field made the same binder appear to start working. The native event is now an alias of the inherited one and `OnBound` calls the base implementation.
- Private `[SerializeReference]` fields no longer disappear from the `MonoView` / `MonoViewModel` / `MonoBinder` inspectors. The reflected field map admitted a private field only when it carried `[SerializeField]`, so a polymorphic field resolved to a null `FieldInfo` and was skipped for every property — a binder's `_converter` or `_customInteractable` was simply not drawn.
- Converters that can only be built in code are no longer offered by the type picker. `GenericFuncConverter` and the private types behind `ToConvert` / `ToConvertSpecific` wrap a delegate no inspector can supply, so picking one produced an instance with a null delegate; they now carry `[TypeSelectorDisplay(Hidden = true)]`.

### Removed

- Internal `FloatingBackgroundElement`, superseded by the FastTools animated dot background.
- `SerializeReferenceDropdown` integration: the `com.alexeytaranov.serializereferencedropdown` dependency, the `[SerializeReferenceDropdown]` attributes on `[SerializeReference]` fields, the assembly references and the `ASPID_MVVM_SERIALIZE_REFERENCE_DROPDOWN_INTEGRATION` version defines. A replacement built into Aspid.FastTools will take its place.

### Fixed

<!-- Only fixes for bugs that actually shipped in a released version (1.0.0–1.0.5) are listed here. Fixes for code introduced during 1.1.0 development are intentionally folded into their corresponding feature bullets above, not listed as standalone fixes. -->

- `NumberToBoolConverter`: the `Inequality` comparison was inverted — it returned the same result as `Equal` instead of its negation. It now returns `true` when the values are not approximately equal (PR #81).
- `DynamicViewModel.Create<…>`: the factory overloads passed only `DynamicPropertyData.Value`, which forced every property to `BindMode.OneTime` and discarded the user-specified `Mode`. The full `DynamicPropertyData` is now passed so the configured `BindMode` is honoured (PR #83).
- `MonoBinder.Unbind()`: the `ProfilerMarker` block was guarded only by `!ASPID_MVVM_UNITY_PROFILER_DISABLED`, breaking compilation on Unity earlier than 2022.1. It now also requires `UNITY_2022_1_OR_NEWER`, matching `Bind()` (PR #84).
- `VirtualizedList`: `OnAdded` / `OnRemoved` bounds-checked the computed view-pool index against `ItemsSource.Count` with a too-loose `<=`. The check now compares `viewIndex < _views.Length` so it picks `Refresh` vs `ResizeContent` correctly (PR #89).
- `ObservableListBinder`: `InitializeList` subscribed to `CollectionChanged` on the original `list` argument while `DeinitializeList` unsubscribed on `List` (which may be a filtered wrapper), leaking the subscription. The subscribe switch now uses `List` (PR #90).
- Slider / Scrollbar command binders: `OnCanExecuteChanged` reinterpreted the 4-byte `float` `Target.value` as the command's generic type `T` via `Unsafe.As`, causing out-of-bounds reads and garbage `CanExecute` values for `long` / `double` commands. Typed overloads now perform proper numeric casts via `ApplyCanExecute` (PR #92).
- Source generator: bindable members whose type was a generic type parameter fell through to the default class case and ignored `enum` / `struct` constraints. The generator now resolves the effective type kind from the parameter's constraints and emits the correct bindable member type (PR #44).
